# Studio Time Machine: app audit and implementation

Date: 5 September 2026. Scope: the native macOS app and its local synchronisation services. The website, Convex backend and JUCE app were outside this audit.

The app already has a substantial recovery and indexing foundation. Its biggest usability problems were competing navigation controls, archive detail exposed too early, silent truncation, and unclear automatic-update status. This pass improves the working library rather than adding a separate dashboard.

## Implemented findings

| Priority | Finding and impact | Result |
| --- | --- | --- |
| P1 | A create event could arrive before its `.als` file existed. A missing fingerprint looked stable, so the new Set could be missed. | Stability probes explicitly handle delayed creation. Temporary-directory regression coverage exercises this ordering. |
| P1 | A newer save could cancel a pending scan after its snapshot paths had been removed from the queue. | Save paths remain queued through completion and carry event versions so a newer event cannot be consumed by an older scan. |
| P1 | The native watcher ignored `FSEventStreamStart` failure and could claim that monitoring was active. | Startup failure now throws an actionable error and releases the failed stream. |
| P1 | Native testing found that switching to an empty Song filter could trigger an AppKit constraints loop and terminate the app. | Disabled content-driven sizing constraints on the existing accessibility-isolation hosting view, which is already sized by its parent. Repeated empty-filter transitions now stay responsive. |
| P1 | A missing or continuously changing file could delay snapshotting a different, stable Set in the same update batch. | Stability is tracked per path. Stable files proceed; changing files remain queued for retry. Regression coverage includes simultaneous missing, changing and stable files. |
| P2 | `LegacySampleUsageDetailView` duplicated the active sample inspector without a caller. | Removed 385 lines of unreachable UI; the active `SampleUsageDetailView` remains. |
| P2 | Project audio silently ended at 24 items; physical Set history displayed every revision immediately. | Explicit expansion for audio and history, with bounded initial views and lazy expanded rows. A selected older revision remains discoverable on entry. |
| P2 | Library rows exposed all main Set files for every Song. | Each Song starts with its newest Set file. Further Set files and native backups expand separately. |
| P2 | `WorkDetailView` repeatedly sorted history and resolved every Session's audio against its revisions for each visible row. | A cancellable background task builds a derived history snapshot once per catalogue generation. Artifact lookup is then keyed by revision. No frame-rate or percentage speedup is claimed without profiling. |
| P2 | Finding unfinished organisation required browsing individual Songs and discovering a collapsed sources section. | Added All Songs, Recently opened and Needs organising views, name/last-save sorting, useful empty states, and a contextual Organise action. These act on virtual organisation and do not move files. |
| P2 | Watch status was spread across technical copy, and users had no clear way to pause it. | Locations provides Update Library and persistent Pause/Resume controls. Diagnostics are disclosed on demand. Offline and sample states retain their meaning. |
| P2 | Sample mode used a separate physical-project tile path, bypassing the production Song list, and shared storage services with the normal library. | Sample and normal libraries now use the same Song/list/grid workflow. Sample storage is isolated in a temporary location; rescans, cache and recent-history persistence cannot touch normal-library state. Removed the sample-only tile. |
| P2 | A second navigation menu, an in-content Back button and an unused shell icon-button wrapper duplicated existing controls. | Removed them. The sidebar and command-bar breadcrumb remain the navigation authorities; the breadcrumb now prioritises the selected physical Session when inspecting a Set. |
| P2 | Every non-latest main Set was labelled CURRENT, and stem export review implied one exact output filename. | Main Sets use SET; stem review describes its folder and filename prefix. The supported Live 12.4.2 automation boundary is visible. |
| P2 | Custom sidebar controls suppressed keyboard focus, and shared button/disclosure motion ignored Reduce Motion. | Restored native focus feedback and selection traits, labelled Back, and respected Reduce Motion in the changed controls. |

## Progressive disclosure model

1. **Find a Song:** browse recognisable sleeves, sort by its latest indexed save, revisit recent work, or isolate organisation reviews. Global Command-F search remains available.
2. **Continue or inspect:** open the Song, select a saved revision, and use Open in Live or Details. Organise appears when the grouping or Artist needs attention.
3. **Go deeper:** expand additional Set files, native backups, version history, linked exports or Session sources when they matter.
4. **Manage the library:** Locations owns folder availability and watching controls. Scan timings and parser counts stay under diagnostics.

This follows Apple's guidance to keep essential controls visible and disclose advanced information near its context: [Disclosure controls](https://developer.apple.com/design/human-interface-guidelines/disclosure-controls). The existing graphite shell, warm workspace, lime accent and project-sleeve objects remain the design authority.

## Incomplete capabilities and next product work

These are open product capabilities, not claimed as implemented by this pass:

- **Physical file synchronisation:** automatic updates currently keep the local index and observed save history current. A two-folder mirror, cloud transfer, automatic move or overwrite is not implemented. A future copy workflow needs source/destination review, collision handling, content verification, offline recovery and an explicit execution policy.
- **Collections:** the domain language names virtual Collections, but the app has no Collection model or browsing surface. Add persistent virtual Collections for releases, clients and deliverables without changing physical paths.
- **Reusable task recipes:** recovery and Live export exist as individual reviewed actions. A durable queue for repeated stem exports, handoffs and recovery recipes would save more repetitive work; it needs per-job evidence, cancellation and restart semantics.
- **Live automation coverage:** automated export is experimental and restricted to the implemented Live 12.4.2 adapter. Broader versions, unattended rendering and whole-Set merging are not supported capabilities. Existing audio, approximate reconstruction and Live-controlled export must retain separate labels.
- **Research integration:** transformed-sample and musical-version research code exists behind research/calibration boundaries. It is not a shipped product workflow and should not appear as a dependable automation action.
- **Further engineering:** `StudioLibraryStore` still concentrates navigation, search, sample operations, exports and recovery. Split along these existing domain boundaries as behaviour changes, keeping one authoritative state owner for each operation. Broad mechanical extraction alone would not improve the user's workflow.

## Follow-up: floating player clips

The floating player now selects and trims excerpts, edits In/Out seconds, zooms the decoded waveform, and auditions or loops the selection. Copy Clip runs a reviewed local plan into a unique persistent Studio Clips destination, verifies its PCM frame count and format, and writes the file URL to the native pasteboard. Drag Clip and Reveal use that same file. Original audio is read-only. Export is 32-bit float WAV at source rate and channel count (mono/stereo, up to 192 kHz), without normalisation, fades, or Ableton processing. Approximate source previews keep an Approximate filename prefix. Range/source/fidelity changes invalidate pending clipboard completion; copied files remain available for DAW references. Location exposes the full selectable destination and retention explanation.

Observed native checks used an ARTWORK tracking take: drag selection, separate handle adjustment, In/Out editing to 1.000–3.000 seconds, zoom, looping, pause, and Copy Clip. `afinfo` verified the resulting WAV as 96,000 mono Float32 frames at 48 kHz, exactly 2.000000 seconds. Normal and minimum-width windows were inspected, including the inspector and the post-copy controls; actions and numeric fields wrap correctly. The main content reserves extra editor height. Native UI copy returned the success state; source immutability, float headroom, invalid ranges, destination collisions and cancellation also have generated-fixture tests.

The full Swift test run passed **535 tests across 55 suites** in 61.583 seconds. This includes 5 exporter tests and 5 regional-waveform tests. An earlier attempt was interrupted by a test file changing during compilation; the completed run above supersedes it. The unchanged research cancellation test also passed in this full run.

Ableton's [Browser manual](https://www.ableton.com/en/live-manual/12/working-with-the-browser/) documents dragging Finder files into Live, and its [audio-format guidance](https://help.ableton.com/hc/en-us/articles/211427589-Supported-Audio-File-Formats) supports this WAV format. A native Live inspection was attempted but blocked by a ScreenCaptureKit capture failure; no destination Set was edited. Command-V importing from an external file-URL clipboard remains unverified. The UI therefore provides Drag Clip and does not promise direct Live clipboard insertion.

Final confirmation: the packaged native app rebuilt and launched, strict code-signature verification passed, Swift formatting lint and the scoped whitespace check passed. On the final bundle, a long real source file showed labelled zoom bounds and a full selectable destination popover.
